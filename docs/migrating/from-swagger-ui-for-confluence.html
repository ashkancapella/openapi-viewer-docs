Migrating from Swagger UI for Confluence (Tech Labs) to OpenAPI Viewer

If your Confluence Cloud pages show an OpenAPI or Swagger spec with Swagger UI for Confluence by Tech Labs, this guide moves them to OpenAPI Viewer, an app built on Atlassian Forge and designed to be Runs on Atlassian: no outbound traffic, no stored credentials. The old app is small and simple, so most sites finish in one sitting.

Facts about the old app were checked on 13 October 2026 against its Marketplace listing and vendor documentation.

Why migrate now

Atlassian ends support for the Connect framework on 31 January 2027, and warns that breakages will increase afterwards. Since July 2026, Confluence admins have seen a banner on apps that still run on Connect, saying the platform will be unsupported after that date.

Swagger UI for Confluence is a Connect app (version 1.0.15-AC). Its latest release is dated 24 April 2025, which upgraded the bundled Swagger UI to 5.21.0, and its listing shows no Forge version.

Five steps

  1. Export each spec. Open the page in the editor, open the Swagger UI macro, and copy the body into a file such as openapi.yaml. If the macro points at a URL, download the file from that URL, or note which repository path it comes from.
  2. Attach it, or set up CI push. A spec under about 150 KB can be pasted into the new macro. A larger one, or one that used to be loaded from a URL, is attached to the page. To keep it current after every merge, add the pipeline from Push your spec from CI; ready-made pipelines are on that page.
  3. Install OpenAPI Viewer and replace the macro. Install it beside the old app (30-day trial). On each page add the new macro, choose Paste or Attachment, then delete the old macro. See the quick start and attachment mode.
  4. Verify. Reload each page as a normal reader. Check that all paths and schemas render, deep links to operations work, and dark mode looks right. Start with your most visited page.
  5. Delete the old app. After every page is checked, uninstall Swagger UI for Confluence well before 31 January 2027. Keep your page list as a record.

What you lose, and why

  • Loading from a URL. If your spec lived at a URL, that is outbound traffic from the page, which Runs on Atlassian does not allow. Put the file on the page as an attachment instead.
  • Try it out. If your old setup let readers send live requests, that capability needs external permissions on Forge, and an app with external permissions cannot be Runs on Atlassian. See the FAQ. Test requests from Postman, curl or your gateway console.
  • Private specs. Rather than give an app a token for your repository, your pipeline uploads the spec as a page attachment using your own Confluence token, kept in your CI secret store. The app never reaches your repository and never holds a credential.
